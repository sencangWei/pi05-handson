## 已实施的修复及验证

`scripts/simulation_lab.py:bowl_penetrations/move_bowl` 在物体位置更新并forward后，检查目标碰撞几何与外物的接触；穿透超过1毫米就拒绝加载并说明重叠。拒绝时恢复原碗qpos/qvel并刷新观测，不推进物理步；正常静置微接触容忍。

回归测试先复现旧代码接受12毫米穿透，再确认新代码拒绝并回退。16项仿真控制流测试、23项人工接管测试和Ruff通过。独立真实MuJoCo检查：049和零偏移放行，050/051拒绝；拒绝后完整仿真状态逐元素恢复，物理步数为0。证据见 `guard-check.json`、`quadrant-check.json`。

**当前已打开的旧GUI进程不会热加载此函数，重开面板后才使用新防护。** 调查没有强制关闭用户窗口、改当前模型或改原始示范。该修复只解决初始穿透检查，不代表机械臂已经学会恢复或快速搬运。

## 输入能力说明更正

先前聊天中将“记录了8维状态”说成“模型实际使用8维状态作为条件输入”不准确。当前 `pi05=True, discrete_state_input=False`，8维状态虽记录、传入和归一化，但既未作为离散token进入prompt，也未注入连续状态分支；实际条件是RGB＋语言。这与当前README及固定上游pi05 LIBERO配置一致，是已有能力边界，不是这轮新引入的接线回归。

源码、公开4400帧及人工57个首中末抽样的接口审计未发现新的RGB翻转、状态动作错位、单位或窗口拼接错误；轴角超过π也存在于公开数据，不能据此定性为新编码bug。不能只在服务端开启状态输入，必须单独训练和评测；也不能认定它是慢动作的唯一根因。见 `interface-audit.json`。
