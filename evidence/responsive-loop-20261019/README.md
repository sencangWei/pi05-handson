# 交互速度修复（2026-10-19）

已实现并切换到新版交互循环，保留当前`negative_quadrants_20261019/1999`权重、动作幅度和replan=1。没有重新训练。旧示范来源脚本`simulation_lab.py`完全未修改，8条teacher的全部源码哈希依赖仍匹配。

## 已改内容

- 新增`ResponsiveSimulationLab`，状态不变、暂停或等待推理时只同步原生窗口，不重复重建两路相机；仍检查物理状态变化、暂停/单步/退出标志，保留旧预测丢弃机制。
- 控制周期从请求开始计时，推理与物理执行已耗掉的时间不再之后另加50ms等待；活动时Tk轮询30→10ms。
- 独立`timing.csv`记录RPC等待、服务端推理、返回后排队、主线程应用阶段、动作间隔及观测末端位移。原`actions.csv`格式保持兼容。界面显示最近步频/推理等待/观测位移。
- 连续60控制步满足On、开爪命令、实际爪距≥6cm、末端离碗≥10cm且碗漂移≤5mm后，重新获取一次当前几何确认，再自动暂停保存，避免完成后一直跑到800上限。人工纠正不触发这个自动结束。

这套交互暂停规则允许失败后重新取得60步稳定，**不是冻结评测中“首次10步事件后50步”计分的替代**。旧模型实验成绩不重算，不把本次界面修改称为模型恢复能力提升。

## 真实模型与物理的400步对照

同一个保存初态、同一权重、独立8756服务每个连接seed0、JIT预热后各400步。计时排除启动/编码，包含真实π0.5推理、MuJoCo物理及EGL双摄。驱动使用手动轮询，**不包含Tk控件、原生窗口及合成器，因此不是完整GUI的提速百分比**。

| 项目 | 旧循环 | 新循环 |
| --- | ---: | ---: |
| 400步耗时 | 62.64秒 | 39.54秒 |
| 每秒步数 | 6.39 | 10.12 |
| RPC总耗时 | 26.79秒 | 26.62秒 |

该对照环路耗时减少 **36.9%**。400步动作7维逐位相同，输入状态最大差异2.7e-15；逐步完整92维物理状态最大差异4.515e-11。变化发生在执行调度，没有通过放大动作来取得提速。

### 保留的严格校验失败与数值边界

原始要求物理逐位相同的门未通过，`verified/comparison.json`保留`TRAJECTORY_MISMATCH`，不改写成PASS。首次研究的`post_eef`返回观测最多差5.25mm，但该次原始动作/前状态/最终物理状态完全一致；LIBERO返回观测存在缓存，不能把它当作完整积分状态。

第二次加入每步完整物理状态记录。动作逐位相同，物理差异最大4.515e-11。事后明确使用1e-9工程容差作核查，结果满足；不声称该容差事先预声明或物理逐位复现。两次独立legacy重复的最终完整状态向量也有差异，未单独归因，因此不保证跨次运行确定性。原始失败、两次完整记录和工程判读均保留，见[数值核查](engineering-equivalence.json)。

计时后只追加了自动结束时的当前几何确认，该回调在固定400步对照里关闭，所以不影响此调度数据；精确计时版本源码保存于`verified/responsive/benchmarked-responsive-lab.py`，当前版本仅`_check_completion`方法有差异，另有单元和真实物理检查。[版本与验证记录](verification.json)。

## 验证

- 121项测试及5个subtest通过，覆盖等待/暂停免重绘、原生状态修改、旧预测丢弃、单步、重置、节奏、日志隔离、60步完成、缓存几何复查、工作台和人工纠正；Ruff通过。
- 在实际MuJoCo物理中使用明确标记的**合成零位移开爪保持指令**检查完成门，60步后暂停保存，调用学习模型0次。`synthetic-gate-smoke/`仅证明结束条件，**不是训练策略成功演示**。
- 程序没有修改动作幅度、预测窗口或训练集。模型在部分布局预测很小动作的现象仍在；这次减少每步墙钟耗时，没有减少策略解决任务所需的步数。
- `apply_tick_s`包含观测、物理、记录等主线程工作，不能当作纯物理时间；某些CSV post字段来自LIBERO缓存观测，不能用于声称物理逐位一致。动作间隔在人工单步时可含用户等待。
